# ATen Op Config — Design

## Problem

The ATen schema (from `native_functions.yaml`) is currently only available at
**code-generation time**: `Aten_func_ast.t` values are parsed and consumed by
`bin/aten_ops_gen.ml` to produce `.h`, `.cpp`, `.ml` artifacts, then discarded.
At runtime, the interpreter has no typed record of which arguments an operation
takes — it relies entirely on the generated `interp_dispatch.ml` match arms.

The native bridge and verification harness need to know per-op structure at
runtime (which args are tensors vs scalars, what defaults apply, how many
outputs) without pulling in the YAML parser or codegen libraries.

## Solution: Generated `aten_op_config.ml`

A new artifact, `lib/aten_config/aten_op_config.ml`, is generated by
`bin/aten_ops_gen.ml` alongside the existing four artifacts.  It embeds the
schema of every curated op as a plain OCaml `let` binding with no runtime
dependencies.

### Generator: `lib/aten_gen/aten_config_gen.ml`

Driven by the same curated `selection` list as the existing generator.  For each
op that `Aten_decode_gen.dispatch_arm` can handle (same supported type set), it
emits one record.  Ops with unsupported types (or `out` params) are silently
omitted — the bridge treats them as Skipped.

### Runtime type schema

```ocaml
type param_type =
  | Tensor | Tensor_opt | Tensor_list
  | Int | Int_opt | Int_list | Int_list_opt
  | Float | Float_opt
  | Bool | Bool_opt
  | Scalar | Scalar_opt
  | Scalar_type_opt | Layout_opt | Memory_format_opt | Device_opt
  | Str

type default_ =
  | D_none | D_bool of bool | D_int of int | D_float of float
  | D_str of string | D_ints of int list | D_ident of string

type param = { name : string; ty : param_type; default : default_ option;
               kwonly : bool }

type return_arity = Single | Tuple2 | Tuple3

type t = {
  target   : string;        (* "torch.ops.aten.add.Tensor" *)
  base     : string;        (* "add" *)
  overload : string option;
  params   : param list;    (* positional ++ kwarg_only; no out-params *)
  returns  : return_arity;
}

val all  : (string * t) list
val find : string -> t option
```

### Key properties

- **No runtime deps** on `aten_schema`, the YAML parser, or codegen libs.
- **Same curated set** as the CTYpes bindings and dispatch arms — the three
  artifacts never drift.
- **Float defaults** are preserved as their original YAML strings (e.g. `"0.5"`)
  emitted directly as OCaml float literals so no precision is lost.
- **`all` / `find`** enable O(n) lookup over ~40 ops (adequate for dispatch).

### Files

| Path | Role |
|------|------|
| `lib/aten_gen/aten_config_gen.ml` | Generator (new) |
| `lib/aten_config/dune` | Library + rule |
| `_build/default/lib/aten_config/aten_op_config.ml` | Generated artifact |

The `lib/aten_gen/dune` `modules` field lists `aten_config_gen` explicitly so it
participates in the `aten_gen` library alongside the existing generators.
